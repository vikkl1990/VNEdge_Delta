# Local Paper Runtime

The scanner sidecar (`vnedge.dashboard.scanner_live`) is an observation-only
dashboard. It cannot create paper fills because it does not construct a paper
broker, order manager, or simulated exchange.

For paper trades, run the multi-lane runtime instead. It shares one process for
live public data, strategies, the pre-trade risk gateway, simulated fills,
reconciliation, journals, and the read-only dashboard. It mounts no live order
adapter.

## Start

Stop any process already using port 8080, then run:

```bash
export DASHBOARD_TOKEN="<local token>"
scripts/start_local_paper_dashboard.sh
```

The dashboard is available at:

```text
http://127.0.0.1:8080/?token=<local token>
```

## Default paper roster

The launcher deliberately keeps rejected strategy families pruned. The
current code-level roster is generated by
`vnedge.runtime.multi_lane_shadow.desired_lane_specs()` and normally includes:

- BTC funding mean-reversion PAPER on Binance USD-M.
- BTC funding mean-reversion PAPER on Bybit.
- DOGE trend/ATR PAPER on Binance USD-M.
- Matching shadow/research lanes needed for comparison.

Delta funding mean-reversion remains shadow-only because Delta's historical
funding coverage does not satisfy the same warmup contract. The rejected Delta
scalper scanners remain disabled; they must not be re-enabled merely to create
dashboard activity.

## What “working” means

Immediately after startup the dashboard should show PAPER lanes, a simulated
account, live evaluations, and writable journals under `logs/paper_trials`.
A fill is not expected immediately: the retained strategies use 1h decision
bars and selective funding/trend conditions. Runtime health and signal
frequency are separate questions.

The process is still paper-only even when an entry fires:

- no exchange API key is required;
- no live execution adapter is mounted;
- fills occur inside `SimulatedExchange`;
- every intent still passes `PreTradeRiskGateway`;
- journals and account state are persisted per lane.
